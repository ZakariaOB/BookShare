# BookShare Product Vision

## Purpose

BookShare should help people make books they own discoverable and connect with one another to arrange an exchange. The first milestone is a complete, usable path from creating an account to connecting after an exchange decision.

## Product mindset

BookShare is an ongoing product, not a time-boxed experiment. There is no artificial deadline for finishing the application. Progress is measured by useful, validated product increments and by what is learned from real users.

The working loop is:

**Understand -> Design -> Build -> Deploy -> Observe -> Learn -> Improve**

## Development principles

- Start with the user problem and intended experience, then make requirements and acceptance criteria explicit.
- Discuss domain and architectural implications before significant implementation.
- Deliver small, useful increments that keep the product deployable.
- Validate assumptions with users and use the evidence to adjust the product.
- Keep architecture clean but proportional to current needs.
- Separate business rules from infrastructure when that separation creates clarity or testability.
- Use real product problems to learn and practise software architecture.
- Avoid speculative abstractions, premature scaling, distributed systems without a demonstrated need, and broad rewrites without product value.
- Keep product and architecture decisions explicit and understandable; use Codex to accelerate implementation, exploration, refactoring, and tests rather than to make major decisions silently.
- Sustain development alongside professional work and other activities.

The preferred collaboration flow is:

**Product discussion -> requirements -> architecture discussion -> small agreed task -> implementation -> tests -> review -> merge -> next iteration**
